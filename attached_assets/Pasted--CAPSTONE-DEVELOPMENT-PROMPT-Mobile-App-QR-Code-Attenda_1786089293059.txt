# CAPSTONE DEVELOPMENT PROMPT

## Mobile App QR Code Attendance System

Develop a complete **Mobile App QR Code Attendance System** for a school/university.

The system will have three main roles:

1. **Student**
2. **Officer**
3. **Admin**

The main purpose of the system is to record student attendance using a **single event QR code generated by the Admin**, while allowing the Officer to verify the student's identity using the student's registered profile photo.

---

# IMPORTANT QR CODE REQUIREMENT

The QR code used for attendance is an **EVENT QR CODE**.

### The Admin is the ONLY user who can:

* Create an event
* Generate the event QR code
* Print the event QR code
* Distribute the printed event QR code

### The Student must NOT:

* Generate an event QR code
* View the event QR code in the Student Portal
* Download the event QR code
* Display the event QR code

The Student Portal should only provide the student's own account information, profile, and attendance records.

The **Officer scans the printed Event QR Code** during attendance.

# 14. SCANNING FLOW

The attendance process should work as follows:

### Step 1

Admin creates an event.

### Step 2

Admin configures the attendance sessions.

### Step 3

Admin generates ONE event QR code.

### Step 4

Admin prints the QR code.

### Step 5

Printed QR code is placed/distributed at the event.

### Step 6

Officer opens the Officer Scanner.

### Step 7

Officer scans the printed Event QR Code.

### Step 8

System determines the active attendance session.

Example:

**Event:** Acquaintance Party 2026

**Current Session:** Morning IN

### Step 9

System asks the Officer to identify/verify the student.

### Step 10

The Officer scans or enters the student's identity information according to the implemented attendance flow.

### Step 11

System retrieves:

* Student Name
* Student ID
* Year Level
* Student Profile Photo

### Step 12

The student's photo is displayed.

### Step 13

Officer visually verifies the student.

### Step 14

Officer presses:

**CONFIRM ATTENDANCE**

### Step 15

System saves:

* Student
* Event
* Session
* Date
* Time
* Officer
* Attendance Status

# 15. ATTENDANCE RECORD STRUCTURE

Each attendance record must identify the specific session.

Example:

| Student        | Event              | Session      | Date  | Time     | Officer    |
| -------------- | ------------------ | ------------ | ----- | -------- | ---------- |
| Juan Dela Cruz | Acquaintance Party | Morning IN   | Aug 7 | 7:45 AM  | Officer 01 |
| Juan Dela Cruz | Acquaintance Party | Morning OUT  | Aug 7 | 11:30 AM | Officer 01 |
| Juan Dela Cruz | Acquaintance Party | Afternoon IN | Aug 7 | 1:00 PM  | Officer 02 |

This allows the system to track the student's complete attendance throughout the event.

---

# 16. DUPLICATE SCAN PROTECTION

A student must only be allowed to record attendance once for each session.

For example:

Juan Dela Cruz:

**Morning IN**

Already recorded at 7:45 AM.

If scanned again at 8:00 AM:

Display:

**"Attendance already recorded for Morning IN."**

But the student can still attend:

* Morning OUT
* Afternoon IN
* Afternoon OUT
* Evening IN
* Evening OUT

because those are separate attendance sessions.

The database must enforce this rule.

Use a unique attendance constraint based on:

**Event + Student + Session**

The backend must validate:

* Event
* Event status
* Current attendance session
* Officer authorization
* Student
* Duplicate attendance

* Event is inactive
* No attendance session is currently active
